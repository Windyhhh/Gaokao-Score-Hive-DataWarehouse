## 二、课程设计意义与目的

### 2.1 项目背景
高考招生数据涉及多个维度（时间、地点、高校、批次等），数据量大且结构复杂。传统的关系型数据库难以高效处理多维度的复杂查询。

### 2.2 设计意义
- **数据仓库设计**：学习星型模式架构，理解维度建模的核心思想
- **ETL处理**：掌握大数据集的清洗、转换、加载流程
- **OLAP分析**：实践8类OLAP操作，理解多维数据分析的方法
- **Hive应用**：学习使用Hive进行大规模数据处理和分析

### 2.3 项目目标
构建一个完整的高考招生数据仓库系统，实现对天津、青海、广西三省2014-2019年高考招生数据的多维度分析。

### 3.3 功能模块

#### 3.3.1 Drill Down（下钻）
**实际意义**：从粗粒度向细粒度钻取数据，如从年度数据钻取到省份数据

**查询示例1**：年度→省份维度下钻
```sql
SELECT year, location, COUNT(*) as count, AVG(avg_score) as avg_score
FROM gaokao_admission_fact f
JOIN time_dimension t ON f.year_id = t.year_id
JOIN location_dimension l ON f.location_id = l.location_id
WHERE year = 2019
GROUP BY year, location
ORDER BY avg_score DESC;
```

**查询示例2**：批次→省份维度下钻
```sql
SELECT batch, location, COUNT(*) as count, AVG(avg_score) as avg_score
FROM gaokao_admission_fact f
JOIN batch_dimension b ON f.batch_id = b.batch_id
JOIN location_dimension l ON f.location_id = l.location_id
WHERE batch = '本科一批'
GROUP BY batch, location
ORDER BY avg_score DESC;
```

#### 3.3.2 Roll Up（上卷）
**实际意义**：从细粒度向粗粒度汇总数据，如从高校年度数据汇总到年度数据

**查询示例1**：高校年度→年度汇总
```sql
SELECT year, AVG(avg_score) as avg_score, COUNT(*) as count
FROM gaokao_admission_fact f
JOIN time_dimension t ON f.year_id = t.year_id
GROUP BY year
ORDER BY year;
```

**查询示例2**：高校省份→省份汇总
```sql
SELECT location, AVG(avg_score) as avg_score, COUNT(*) as count
FROM gaokao_admission_fact f
JOIN location_dimension l ON f.location_id = l.location_id
GROUP BY location
ORDER BY avg_score DESC;
```

#### 3.3.3 Slice（切片）
**实际意义**：在某一维度上选择特定值，如选择2019年的所有数据

**查询示例1**：2019年数据切片
```sql
SELECT university, batch, avg_score
FROM gaokao_admission_fact f
JOIN time_dimension t ON f.year_id = t.year_id
JOIN university_dimension u ON f.university_id = u.university_id
JOIN batch_dimension b ON f.batch_id = b.batch_id
WHERE year = 2019
LIMIT 20;
```

**查询示例2**：天津市数据切片
```sql
SELECT year, university, batch, avg_score
FROM gaokao_admission_fact f
JOIN time_dimension t ON f.year_id = t.year_id
JOIN location_dimension l ON f.location_id = l.location_id
JOIN university_dimension u ON f.university_id = u.university_id
JOIN batch_dimension b ON f.batch_id = b.batch_id
WHERE location = '天津'
LIMIT 20;
```

#### 3.3.4 Dice（切块）
**实际意义**：在多个维度上同时选择特定值，如选择2019年天津市的数据

**查询示例1**：多维度同时选择
```sql
SELECT university, batch, candidate_type, avg_score
FROM gaokao_admission_fact f
JOIN time_dimension t ON f.year_id = t.year_id
JOIN location_dimension l ON f.location_id = l.location_id
JOIN batch_dimension b ON f.batch_id = b.batch_id
JOIN candidate_type_dimension c ON f.candidate_type_id = c.candidate_type_id
WHERE year = 2019 AND location = '天津' AND batch = '本科一批'
LIMIT 20;
```

**查询示例2**：广西文理科对比
```sql
SELECT candidate_type, AVG(avg_score) as avg_score, COUNT(*) as count
FROM gaokao_admission_fact f
JOIN location_dimension l ON f.location_id = l.location_id
JOIN candidate_type_dimension c ON f.candidate_type_id = c.candidate_type_id
WHERE location = '广西'
GROUP BY candidate_type
ORDER BY avg_score DESC;
```

#### 3.3.5 Top N（前N名）
**实际意义**：找出排名前N的数据，如找出2019年平均分最高的10所高校

**查询示例1**：2019年平均分最高的10所高校
```sql
SELECT university, AVG(avg_score) as avg_score, COUNT(*) as count
FROM gaokao_admission_fact f
JOIN time_dimension t ON f.year_id = t.year_id
JOIN university_dimension u ON f.university_id = u.university_id
WHERE year = 2019
GROUP BY university
ORDER BY avg_score DESC
LIMIT 10;
```

**查询示例2**：天津理科本科一批前15所高校
```sql
SELECT university, avg_score
FROM gaokao_admission_fact f
JOIN location_dimension l ON f.location_id = l.location_id
JOIN batch_dimension b ON f.batch_id = b.batch_id
JOIN candidate_type_dimension c ON f.candidate_type_id = c.candidate_type_id
JOIN university_dimension u ON f.university_id = u.university_id
WHERE location = '天津' AND batch = '本科一批' AND candidate_type = '理科'
ORDER BY avg_score DESC
LIMIT 15;
```

#### 3.3.6 Bottom N（后N名）
**实际意义**：找出排名后N的数据，如找出平均分最低的高校

**查询示例1**：2018-2019年平均分最低的10所高校
```sql
SELECT university, AVG(avg_score) as avg_score, COUNT(*) as count
FROM gaokao_admission_fact f
JOIN time_dimension t ON f.year_id = t.year_id
JOIN university_dimension u ON f.university_id = u.university_id
WHERE year IN (2018, 2019)
GROUP BY university
ORDER BY avg_score ASC
LIMIT 10;
```

**查询示例2**：青海本科二批最低的12所高校
```sql
SELECT university, avg_score
FROM gaokao_admission_fact f
JOIN location_dimension l ON f.location_id = l.location_id
JOIN batch_dimension b ON f.batch_id = b.batch_id
JOIN university_dimension u ON f.university_id = u.university_id
WHERE location = '青海' AND batch = '本科二批'
ORDER BY avg_score ASC
LIMIT 12;
```

#### 3.3.7 Tertile（三分位数）
**实际意义**：将数据分为三个等分，分析数据分布

**查询示例1**：2019年三省理科分数三分位分布
```sql
SELECT location, candidate_type,
  PERCENTILE(avg_score, 0.33) as q1,
  PERCENTILE(avg_score, 0.67) as q2,
  PERCENTILE(avg_score, 1.0) as q3
FROM gaokao_admission_fact f
JOIN location_dimension l ON f.location_id = l.location_id
JOIN candidate_type_dimension c ON f.candidate_type_id = c.candidate_type_id
JOIN time_dimension t ON f.year_id = t.year_id
WHERE year = 2019 AND candidate_type = '理科'
GROUP BY location, candidate_type;
```

**查询示例2**：本科一批各年度三分位趋势
```sql
SELECT year, batch,
  PERCENTILE(avg_score, 0.33) as q1,
  PERCENTILE(avg_score, 0.67) as q2,
  PERCENTILE(avg_score, 1.0) as q3
FROM gaokao_admission_fact f
JOIN time_dimension t ON f.year_id = t.year_id
JOIN batch_dimension b ON f.batch_id = b.batch_id
WHERE batch = '本科一批'
GROUP BY year, batch
ORDER BY year;
```

#### 3.3.8 Quartering（四分位数）
**实际意义**：将数据分为四个等分，分析数据分布的更细粒度

**查询示例1**：2018-2019年三省四分位分布
```sql
SELECT location,
  PERCENTILE(avg_score, 0.25) as q1,
  PERCENTILE(avg_score, 0.5) as q2,
  PERCENTILE(avg_score, 0.75) as q3,
  PERCENTILE(avg_score, 1.0) as q4
FROM gaokao_admission_fact f
JOIN location_dimension l ON f.location_id = l.location_id
JOIN time_dimension t ON f.year_id = t.year_id
WHERE year IN (2018, 2019)
GROUP BY location;
```

**查询示例2**：文科vs理科四分位对比
```sql
SELECT candidate_type,
  PERCENTILE(avg_score, 0.25) as q1,
  PERCENTILE(avg_score, 0.5) as q2,
  PERCENTILE(avg_score, 0.75) as q3,
  PERCENTILE(avg_score, 1.0) as q4
FROM gaokao_admission_fact f
JOIN candidate_type_dimension c ON f.candidate_type_id = c.candidate_type_id
GROUP BY candidate_type;
```

### 3.4 主要问题与解决方案

#### 问题1：Hive元数据初始化失败
**问题描述**：Hive启动时报错"Unable to instantiate SessionHiveMetaStoreClient"

**根本原因**：Derby数据库元数据损坏或未正确初始化

**解决方案**：
1. 清理所有元数据目录
2. 使用schematool强制重新初始化
3. 重启Hadoop和Hive服务

#### 问题2：HQL语法错误
**问题描述**：原始OLAP脚本中使用中文别名导致解析错误

**根本原因**：Hive解析器对复杂中文别名的支持不完善

**解决方案**：
1. 将所有中文别名改为英文
2. 创建hive_olap_analysis_fixed.hql
3. 所有16条查询全部执行成功

#### 问题3：数据编码问题
**问题描述**：原始CSV文件使用GBK编码，导致中文乱码

**根本原因**：Python默认使用UTF-8编码

**解决方案**：
1. 在data_preprocessing.py中指定GBK编码
2. 输出为UTF-8编码的CSV和TSV文件
3. 数据正确显示
